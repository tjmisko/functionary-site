the browser, send notes (often with screenshots), and we change it. Expect that
to continue. Nothing here is final.

## How the figure works

**One clock.** Every animated element is a CSS animation delayed to its window
on one timeline. The `T` table at the top of `FlowHero.astro` names every
moment in seconds. The helpers `win(t0, t1)` (fade in at `t0`, out at `t1`) and
`draw(t0, dur, t1)` (stroke a path) turn those into `style` strings. An element
with no end time gets the class `final` and survives to the last frame.

**The script** pauses every animation and sets its time itself. That gives
play, pause, a scrubbable playbar, scroll-driven stepping, and `?t=<seconds>`
to freeze a frame. Without JS the animations just play. With reduced motion
only `final` elements show.

**Scroll.** On the home page the figure sits in a tall section
(`[data-hero-scroll]`, `760vh`) inside a sticky pin. It autoplays until the
reader scrolls; then scroll position sets the clock and the figure eases to it.
Under 860px the pin is off and it just plays.

**3D.** The scene is flat layers in a CSS 3D world. The camera is one transform
on `.world` (`fh-cam` keyframes, built in the frontmatter `css` string). Only
the Replicate beat turns the camera. The Replicate lanes are separate layers
lifted in depth; the flip cards are real two-faced 3D elements.

**To add or move a beat:** add a time to `T`, add a caption to `captions` (each
caption is one beat, and the playbar ticks and the harness's beat list come
from it), then give the new elements windows with `win`/`draw`. Later times in
`T` are absolute, so shift them by hand.

## Checking beats: the harness

The harness loads the figure in headless Chrome with the clock frozen and takes
stills. It needs the dev server up, `chromium-browser` or `google-chrome`, and
ImageMagick.

```
# 1. dev server (from anywhere)
npx astro dev --port 4391 --root ~/.worktrees/functionary-site/site/reproducibility-pitch

# 2. one settled frame per beat, plus a labelled contact sheet
node scripts/hero-frames.mjs --beats --out .frames/beats --cols 4

# particular moments, in seconds
node scripts/hero-frames.mjs 21.4 22.0 24.6

# a range
node scripts/hero-frames.mjs --from 27 --to 37 --step 0.5

# bigger frames, to read small text
node scripts/hero-frames.mjs --width 1500 --height 760 --cols 1 26.8

# the real home page at a screen size, to check it fits one screen
node scripts/hero-frames.mjs --url http://localhost:4391/ --width 1600 --height 860 --cols 1 21.2
```

Run it from the worktree, or pass absolute paths. Output goes to `.frames/`
(git-ignored): `t-<seconds>.png` per frame and `sheet.png`. Read `sheet.png` to
look at a set at once; read a single frame when detail matters.

`--beats` reads the beat list from the page (`data-beats` on the stage, built
from `captions`) and takes each beat at 90% of its length, when it has settled.
Beats that are mostly motion (the pull-out, the camera turn, the flip) need
extra frames mid-beat to judge.

After every change: run `npx astro check --root <worktree>`, capture the beats
you touched, and look at them before reporting. The harness refuses to capture
a page that answers 500, so a blank sheet means the page is broken.

**What the harness cannot show:** motion, easing, the scroll behaviour, and
anything Firefox-specific. The user watches in Firefox at 120% zoom. Say
plainly that stills were checked and motion was not.

## Gotchas

- **Astro's template parser breaks on `<=` and `>=` in markup expressions.**
  Compute anything with comparisons in the frontmatter and map over the result.
- **`export type` with a leading `|` in an `.astro` frontmatter fails to
  compile.** Types live in `src/lib/flow-nodes.ts`.
- **Chrome drops a lifted 3D layer that paints nothing of its own.** The lane
  layers carry a near-invisible background for that reason. Don't remove it.
- **Opacity on a 3D parent flattens it.** The flip card has no opacity
  animation; its faces do. Putting one on the card shows the front mirrored.
- **A card turning about its middle passes behind the sheet.** `fh-flip` lifts
  it forward mid-turn to clear.
- **Elements must finish fading before `T.end`.** The clock stops there; a fade
  still in progress leaves a ghost on the last frame.
- **The dev server can serve stale scoped styles after a file is rewritten
  wholesale.** `touch` the file and capture again.
- **The dev server gets killed when the machine is low on memory.** Do not
  restart it unasked; tell the user and wait.
- **The harness's Chrome profile dirs** are created under the output directory
  and removed after each run.
- Edits to files in the worktree were made with small Python patch scripts,
  since the worktree is outside the session's working directory. Re-read a
  region before patching it; several blocks have moved more than once.

## Rules the user has set for the figure

- Schematic, between abstract and a rendering of the app. Shapes follow the
  canvas: sources and writes are squares, blocks have a filled header and a
  model dot, gates are hexagons, transforms are grey pills.
- Map uses the canvas's shape (table, funnel, body, funnel, table), not
  brackets. Replicate and Refine still use amber brackets; the canvas has
  shapes for both (`jigs.css`) and the user has not yet asked for them.
- Modules have verb names (Find sources, Prepare data, Weigh evidence). Sheets
  show the flow's name; the `.rs` file name appears only on the source face.
- Don't show all modules all the time. Show them together once when they are
  pulled out, then hide them.
- No dashed lines. Module beams are faint, sit behind the sheets, and join the
  straight part of an edge.
- Avoid wires that run backward. The Refine loop is the one exception.
- Run lines ("squiggles") are faint on flows and are hidden once the Replicate
  point is made. An agent's path is uneven swings with an occasional loop.
- Results are documents. They are hidden when they are not the point.
- No duplicated agent: the left-hand circle is the authoring agent and appears
  only once a flow exists.
- Colleagues appear only in their own beat.
- Captions are plain sentences, one per beat, and must not overlap.
- Use the screen: the figure breaks out of the text column and is sized by the
  window; inside it, don't leave large empty areas.
