## The hero as it stands (about 20 seconds, nine captions)

1. You hand the job to an agent.
2. No flow yet: a large agent glow finds scattered sources and does the work
   its own way, in a long looping path. Results are mixed.
3. You react to the results and to how it got them (rings on bad rows, a mark
   on the agent, an arc back to you).
4. The agent writes what worked into `flow.rs`, revision 1: four small sources
   fan in to a Map holding an Extract block and a smaller Agent, then a Check,
   then Write.
5. The runtime executes it. The run line follows the wires and curls only
   inside model-bearing nodes; it turns green after the Check.
6. You react again; the agent revises.
7. Revision 2: sources, Map [Extract, Format, Grade, Check], one Review after
   the Map, fan-out to Write, Commit, Notify.
8. The sheet tilts and four copies fan out behind it: Replicate, five runs,
   one agent-coloured functionary per run.
9. A results grid per run, a Join column, and rings on the three rows where
   runs disagree. Colleagues appear beside "you" and point at the flow.

Known weak points:

- The 3D is a 2D shear and stack. It cannot orbit.
- Reactions do not travel back and become the new blocks. Revisions
  cross-fade; the Agent does not visibly split into blocks.
- Replicate is drawn as stacked copies of the whole flow, not as a jig.
- The Rust source is never shown.
- "Records the run" appears only as a caption; no receipts are drawn.
- Disagreement data in the last beat is invented.
- "Notify" is drawn as an action though the block has no sender adapter yet.
  The user has not ruled on it.
- The playbar is not scrubbable.

## Next task: true 3D, and the Rust underneath

The user's words: "This is the hero, we should go all out", and "under the
hood, this is really just rust code that's readable and auditable."

### Recommended approach

Use three.js for the scene and keep the SVG version as the fallback.

- **Scene.** Each flow revision is a sheet (a plane in 3D). A perspective
  camera moves along a scripted path: face-on for the loop, then orbiting out
  at the end to reveal the replicas stacked in depth and the join.
- **Sheet content, two options.**
  - *CSS3DRenderer hybrid:* three.js drives the camera, and each sheet is a
    DOM element holding the existing SVG. Text and lines stay vector-crisp,
    `FlowSheet.astro` is reused almost as is, and the Rust panel can be real
    selectable text. No lighting or shader effects on the sheets.
  - *Full WebGL:* draw nodes as shape geometry, wires and the run line as
    fat lines or tubes, text as SDF text, the Agent as a shader glow. More
    work, and the most room for the run line to move through depth.
  - Suggested: start with the hybrid, add a WebGL layer behind it for the
    agent glow and the run line if it needs more.
- **One clock.** Replace the per-element CSS delays with a single timeline
  value that everything reads (a small custom timeline, or GSAP). That makes
  the playbar scrubbable and pause-able, and makes the beats easy to retime.
  The `T` table and the window model in `Lifecycle.astro` carry over directly.
- **Fallbacks.** Without WebGL, with `prefers-reduced-motion`, or before the
  script loads, show the last frame as static SVG (the current component
  already has this state). Load three.js lazily so the page's first paint does
  not wait on it. The site is Astro with no framework; a plain client script
  is enough, and React Three Fiber would add React for no gain.
- **CSS 3D alone** (perspective and `preserve-3d` on HTML layers, no library)
  would give real rotation of flat sheets cheaply. It is the low-cost option
  if three.js turns out to be more than the hero needs.

### Showing the Rust

Idea: the sheet has two faces, or the canvas peels back. The canvas view and
the `flow.rs` text are the same object, and the camera move shows that: flip
or split the sheet so each node lines up with the lines that declare it, with
the run line passing through both.

This collides with the staleness problem and needs a user ruling before it is
built. The ground truth (`flow-language` area) found:

- No snippet on the old site matched any accepted flow.
- On `bleeding` the flow source is a screened Rust-like subset; 45 of 110
  reference flows failed under rustc on 2026-11-15.
- "Flow source is real Rust" is ruled (v3, 2026-11-16) and implemented on
  `integrate/f110`, unmerged. A further retyping (F114) is ruled and unbuilt.

Options to put to the user:

1. Take a real accepted flow from the product repo at build time (a fixture
   or a reference flow), so the hero cannot drift from the language. Best fit
   for "readable and auditable", and it needs a flow on a branch they are
   willing to show.
2. Hand-write a flow in v3 syntax and add a check that compiles it against
   the product's checker.
3. Show Rust-shaped text only (greeked lines with a few real keywords). Safe,
   but it undercuts the claim that the code is readable.

### Motion beats still to build

- A reaction (a ring on a bad row) travels back along the arc and lands as a
  new block or gate in the next revision.
- The Agent glow splits in place into explicit blocks between revisions.
- The agent visibly rewrites `flow.rs` on revisions, not only the first time.
- Receipts drop from each block call as the run passes.

## Standing rules that shaped the work

From the user's global instructions and saved memory:

- Concise and direct. No emoji. Ask focused questions when unsure.
- Work in worktrees under `~/.worktrees/<repo>/<branch>`, created with
  `gh worktree create`. Conventional, atomic commits, only when asked.
- Site copy: plain noun headers, two to four sentences a paragraph, no
  slogans or paired-clause taglines, no em-dashes, no negated benefits, no
  hedging asides. Earlier copy was rejected as "obviously AI" and "cutesy".
- Banned in public copy: harden, ossify, calcify, bureaucracy,
  principal-agent, enframing, spider or web metaphor, and the usual marketing
  vocabulary. Do not name Dennett or Scott on the page; they are the user's
  private lenses.
- Product words: block and block call (not step), Agent (not Sketch agent),
  Test and Run, personal and governed workspace. It is a local server with a
  browser UI and a terminal client, not a "desktop tool".
